# Отчёт: «Полевой архив» — диагностика и исправление ошибок

Найдено и исправлено ровно 7 логических ошибок. Интерфейс, структура модулей и данные не менялись. Номера строк указаны по исходной версии.

| № | Файл, строка | Что было неправильно |
|---|---|---|
| 1 | `validators.py`, 75 | Периоды анализов пересекались только при строгом неравенстве, хотя даты включительные |
| 2 | `repository.py`, 8 | Сортировка по глубине шла как по тексту |
| 3 | `repository.py`, 47–48 | Поиск по названию и категория соединялись через OR |
| 4 | `reports.py`, 9 | Статистика хранилищ завышалась из-за JOIN с таблицей перемещений |
| 5 | `services.py`, 112 | Хранилище «откуда» брался из предыдущего перемещения, а не из текущего положения |
| 6 | `models.py`, 8 | Инвентарный номер не приводился к единому регистру: `ar-2026-0001` и `AR-2026-0001` считались разными |
| 7 | `services.py`, 97–99 (+ `database.py`) | При удалении находки пропадали все записи её истории, включая «Удаление» (`ON DELETE CASCADE`) |

## 1. Пересечение периодов анализа
- **Наблюдение:** у находки №23 есть анализ 2026-10-08 — 2026-10-16. Новый анализ 2026-10-16 — 2026-10-20 создаётся без ошибки, хотя 16 октября занято в обоих.
- **Причина:** `periods_overlap` использует `start_a < end_b and end_a > start_b`, а даты включительные.
- **Исправление:** `start_a <= end_b and end_a >= start_b`.
- **Проверка:** период с 16 октября отклоняется, период с 17 октября принимается.

## 2. Сортировка по глубине
- **Наблюдение:** при сортировке «Глубина (см)» порядок вида 10, 100, 25, 5.5.
- **Причина:** `CAST(f.depth_cm AS TEXT)` превращает число в строку, и сравнение идёт посимвольно.
- **Исправление:** `"depth": "f.depth_cm"`.
- **Проверка:** значения идут по возрастанию (5.5, 5.5, 6.5, 6.5, 7.5, ...), по убыванию в обратном порядке.

## 3. Совместный фильтр «название + категория»
- **Наблюдение:** при вводе текста в поиск и выборе категории появляются находки другой категории или с другим названием.
- **Причина:** при двух активных условиях первые два пункта склеивались как `(… OR …)`.
- **Исправление:** удалил этот блок, все условия объединяются через AND.
- **Проверка:** по `AR-2026-000` и одной категории остаются только записи, которые подходят под оба условия.

## 4. Количество находок в хранилищах (статистика)
- **Наблюдение:** в «Статистике» числа по хранилищам больше фактических, например вместо 6 или 10.
- **Причина:** `LEFT JOIN movements` размножает строки: находка с N перемещениями считается N раз.
- **Исправление:** убрал этот JOIN из `storage_occupancy`.
- **Проверка:** значения по хранилищам: 8, 6, 5, 10, 7 (сумма 36 = число находок).

## 5. Журнал перемещений: «откуда»
- **Наблюдение:** находка 4 лежит в «Реставрационном хранении», ранее её перенесли из «Керамического фонда». При новом перемещении в журнале указано «Керамический фонд → …».
- **Причина:** `origin_id` брался из `previous["from_storage_id"]` (предыдущего перемещения).
- **Исправление:** `origin_id = finding["storage_id"]` (текущее хранилище); ставшую ненужной переменную `previous` удалил.
- **Проверка:** перемещение находки 4 даёт запись «Реставрационное хранение → Металлофонд».

## 6. Регистр инвентарных номеров
- **Наблюдение:** можно создать вторую находку `ar-2026-0001`, хотя `AR-2026-0001` уже есть.
- **Причина:** `normalize_inventory_code` по описанию должна быть нечувствительной к регистру, но регистр не менялся, а в базе нет COLLATE NOCASE.
- **Исправление:** `.upper()` в конце нормализации.
- **Проверка:** `ar-2026-0002` отклоняется как дубликат, новые номера сохраняются в верхнем регистре.

## 7. Потеря истории при удалении находки
- **Наблюдение:** после удаления находки из «Истории изменений» исчезают все её записи, в том числе «Удаление».
- **Причина:** внешний ключ `change_logs.finding_id` объявлен с `ON DELETE CASCADE`, поэтому записи удаляются вместе с находкой (у `movements` используется `SET NULL`).
- **Исправление:** в `delete_finding` записи журнала сначала отвязываются (`finding_id=NULL`), а запись об удалении создаётся без привязки; в схеме `database.py` и в рабочей базе `data/archive.db` ключ заменён на `ON DELETE SET NULL` (данные сохранены, 36 находок и вся история на месте).
- **Проверка:** после создания, изменения и удаления тестовой находки в истории остаются записи «Создание», «Изменение», «Удаление».

## Общая проверка
Сценарии проверены скриптом на копии базы: лабораторные периоды, сортировки, фильтры, статистика, перемещения, создание и удаление находок, перезапуск (повторное открытие базы). Скриншоты из окна программы и из SQLite делаются вручную для сдачи.
